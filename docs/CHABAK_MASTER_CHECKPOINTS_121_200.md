# CHABAK STEP 121–200 체크포인트

검증 환경은 Pleos Connect v2.1.0, Android Automotive API 34, emulator-5554, Android 사용자 10이다. 2026-11-07 기준으로 기록했다. 이전 작업의 변경 파일이 같은 Git 작업 트리에 있어 이번 검증은 체크포인트 문서와 파일 단위 기준으로 남겼다.

## 121–130 · 여행 다이어리

- 기존 앱 공통 일기는 이전 기록 보기에서 열람한다. 기존 여행과 일기의 대응 정보가 없어 자동 연결을 생략했다.
- SQLite v4→v5는 기본값이 있는 diary 열만 추가한다. 여행별 메모·후기·사진 참조·시작/종료 시각을 저장한다. 기존 두 여행의 종전 열 전체를 각각 해시 비교해 일치를 확인했다.
- API 34 Photo Picker에서 테스트용 이미지 두 장을 골랐다. 두 장 모두 앱에서 썸네일로 표시됐고 테스트 메모와 함께 새 여행의 SQLite 행에 기록됐다.
- 첫 체크포인트 결과는 JVM 9/9, 계측 24/24다. 최종 빌드 수치는 종합 보고서를 기준으로 한다.

## 131–140 · 화면 검수

- 홈, 찾기, 추천, 상세, 준비물, 내 여행, 이동, 차박 중, 에너지, 모닝, 환경, 다이어리를 API 34에서 직접 열었다.
- 공통 헤더에 날씨 출처와 모델 기준 시각, 조회 시각을 추가했다. 공개 캠핑장 좌표가 있으면 캠핑장 인근 모델 결과를, 그 외에는 대표지점을 표시한다.
- 기존 네 가지 홈 메뉴, 테마 리소스와 반투명 카드를 유지했다. 화면별 캡처 및 기기 테스트 범위는 종합 보고서에 있다.

## 141–150 · 여행 흐름

- 새 검증용 여행에서 공식 추천 → 장소 선택 → 준비물 → Pleos 목적지 → 안내 종료 → 수동 차박 시작 → 에너지·환경·모닝 → 기록을 확인했다.
- SDK 로그에서 route_started, matched=true, ROUTE_GUIDING을 확인했다. SDK에 도착 콜백은 있으나 이 빌드는 주차 후 사용자가 직접 차박을 시작하는 흐름을 사용한다.
- 시작/종료 이력은 실제 버튼 동작으로만 생성된다. 여행 목록은 계획·차박 중·종료·보관을 표시한다. 여행 목록에서 현재 주행 상태를 지속 추적하는 기능은 보류했다.

## 151–160 · 서버와 데이터

- 에뮬레이터에서 8085 /health, /recommend, /camps가 200을 반환했다. 경기·숲 추천 5개 ID, 대한민국 범위의 경도·위도 5쌍, /camps ID 재조회 좌표 일치를 확인했다.
- 고캠핑 서버는 15분 메모리 캐시와 오류별 상태를 유지한다. 앱 검색은 동일한 진행 중 요청을 중복 발행하지 않으며, 같은 검색의 마지막 정상 목록을 사용할 때에는 수집일과 연결 실패를 표시한다.
- 8086 /health는 응답하지 않았다. INFO·FOOD·상하행 실제 검증은 보류했다. 실행 중인 서버를 재시작하지 않았고 서버 소스를 변경하지 않았다.

## 161–170 · 차량 안전

- 에뮬레이터의 Vehicle SDK가 SoC 100%, 공칭 용량 77.4 kWh를 반환했다. 보호 기준 30%에서 사용 가능 70%p가 표시됐다.
- 환경 조성의 Light Capability 조회가 READ_WRITE, 영역 1개를 표시했다. 실제 차량 기능의 승인 범위는 차량과 환경에 따라 달라진다.
- UI 제한 상태나 상태 미확인 시 휴식·사진·메모·공유 조작은 제한한다. 정확한 알람 권한이 없을 때 대체 알람의 지연 가능성을 표시한다. 최종 실제 알람·오디오 검증은 종합 보고서에 구분했다.

## 171–180 · 통합 실증

- 기기 데이터 초기화 없이 Debug 앱과 테스트 APK를 설치했다. 두 기존 여행의 필드를 비교하고 신규 테스트 여행을 분리했다.
- 에뮬레이터 로그, SQLite 값, UI 표시를 구분해 확인했다. 사진 검증은 생성한 단색 PNG로 진행했다.
- 물리 도착, 실차, 실주행 전환, 귀가 방향 휴게소, 외부 공유 전송은 별도 검증 대상이다.

## 181–190 · 시연 준비

- 시연 절차, 기술 구조, 심사 질문, 화면 캡처와 녹화 절차를 CHABAK_MASTER_DEMO.md에 정리했다.
- 시연에서 공식 고캠핑 응답, 기상 모델, 에뮬레이터 SDK 응답, 규칙 추천, 수동 시뮬레이션을 각각 표시한다.

## 191–200 · 품질과 인수인계

- 사진은 백그라운드에서 미리보기용 크기로 축소 디코딩한다. 날씨 요청은 대상 변경에 맞춰 갱신하고 실패 시 이전 값의 만료 상태를 확인한다.
- Debug 앱의 평문 연결은 10.0.2.2에만 허용한다. 기본 빌드 설정은 평문을 차단하며 앱의 Android 백업을 껐다. 기기 내 여행 데이터와 업데이트 설치는 유지된다.
- 최종 APK, 테스트 수치, 재현 명령, 환경별 제한은 CHABAK_FINAL_MASTER_REPORT.md를 기준으로 한다.

최종 체크포인트는 Python 9/9, Kotlin JVM 10/10, Android 계측 27/27이다. 두 기존 여행은 SQLite v5에서 기존 필드 전체가 일치했고, 신규 검증 여행은 사진 한 장과 메모·후기·시작/종료 시각을 남겨 보관했다.
