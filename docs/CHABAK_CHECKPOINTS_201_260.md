# CHABAK STEP 201–260 체크포인트

## 201–210

- 기존 산출물 6개를 발견했다. 기존 화면 17장을 모두 비교했고 기존 영상 31.98초·1280×720의 프레임과 전체 디코딩을 검사했다.
- 밝은 풍경 위 텍스트 대비, 작은 홈 보조 문구와 다이어리 사진, 작은 뒤로 이동 영역을 우선 수정했다. 일부 이전 캡처는 제목과 실제 화면이 맞지 않아 신규 캡처는 화면 제목 확인 뒤 저장한다.
- 기존 테마 4종과 홈 네 메뉴를 유지하면서 공통 카드 배경과 테두리, 버튼 26sp·최소 64dp, 홈 제목 32sp·카드 최소 104dp, 뒤로 64dp를 적용했다.
- 다이어리 사진을 220×150dp로 키우고 저장할 변경사항 표시와 저장 후 키보드 정리를 추가했다. 차량 조작 제한 전환 시 입력 포커스를 해제한다.
- Python 9개, JVM 10개, 계측 29개 통과. 신규 계측 2개는 제한 전환 시 편집 요소 제거 및 저장 직전 권한 재확인이다.
- 실제 API 34에서 업데이트 및 홈 화면을 확인했다. SQLite 스키마는 v5를 유지했다.

## 211–220

- 별도 검증 여행을 생성해 공식 추천 → 상세 → 여행 저장과 준비물 체크 → 실제 NaviHelper 경로 안내 → 수동 차박 시작 → SDK 에너지 → 규칙 기반 환경 추천을 실행했다.
- SDK에서 목적지 일치와 ROUTE_GUIDING을 확인했고 시스템 내비 안내를 종료한 뒤 수동으로 차박을 시작했다. 도착 이벤트를 만들지 않았다.
- 사용자가 선택한 낮 테마와 자동 밤 테마를 각각 보여줬다. 자연음 재생 후 Audio Focus 요청과 반환을 확인했다.
- 차박 화면의 미연동 음악 장르 표기를 현재 테마로 정리했다. 배경 1920×1080 원본은 IO 작업에서 읽으며 처음 화면의 디코딩 대기를 줄였다.
- 현재 기준선의 여행 3건 모두 전체 열 해시가 일치한다. 새 검증 여행은 4번째 행에 저장된다.
- Python 오류·캐시 HTTP 테스트 4개를 추가해 13개 통과, JVM 10개 통과. 계측 29개 통과 이후 화면 리소스와 문구 변경은 최종 단계에서 다시 실행한다.

## 221–230

- 검증 여행에서 빈 사진 상태 → Photo Picker 예시 사진 2장 → 메모·후기 저장 → 확대 → Android 사진 공유 선택 화면을 실행했다.
- 앱 프로세스를 종료하고 다시 열어 두 사진과 메모·후기·실제 시작/종료 이력을 확인했다. 한 장의 참조를 제거하고 검증 여행을 보관했다.
- 예시 사진은 기존 배경 리소스이며 실제 여행 현장 사진으로 설명하지 않는다. 기존 여행 3건의 전체 열 해시가 일치한다.
- 제한 상태 전환 시 편집 요소 제거와 저장 직전 권한 확인 계측 테스트를 유지한다. 실제 주행 상태의 차량 화면 전환은 미검증이다.
- Python 13개 및 JVM 10개 통과. 최종 계측 결과는 29개 통과다.

## 231–240

- 서버 중단을 대신해 별도 루프백 포트의 격리 HTTP 테스트로 인증 누락·거부·연결 불가·잘못된 응답·빈 결과·캐시 동시 요청을 검증했다. 운영 중인 8085 프로세스는 유지했다.
- 에너지 SDK SoC 100%, 공칭 77.4 kWh, 충전 스위치 꺼짐을 확인했다. 충전 중 여부는 미지원으로 표시한다.
- 모닝 07:00 저장 → 07:01 변경 → 취소 → 1분 시험 예약을 실행했다. 시험 알람은 예정 시각보다 45.005초 늦게 전달됐다. 아침 배경과 종료 후 예약 없음 상태를 실제 캡처했다.
- Python 13/13, JVM 10/10, API 34 Android 계측 29/29로 합계 52개 통과했다. 앱 데이터 유지 업데이트 후 콜드 스타트는 단일 측정에서 1,649ms였다.

## 241–250

- 원본 90초·85초·180초·150초의 1920×1080 화면 녹화 네 편을 확보했다. 실제 공식 데이터·내비·SDK 에너지·시험 알람·다이어리를 포함한다.
- 대기·반복 조작 일부를 잘라 실제 시간 순서로 연결했다. 편집 구간표와 무음 녹화라는 제한을 시연 문서에 기록했다.
- 4분 54.93초, 1920×1080, H.264 30fps의 편집 영상을 만들고 전체 프레임 디코딩과 장면 샘플·마무리 자막을 검사했다.
- Python 13개, JVM 10개, 계측 29개로 코드 기준선은 그대로다. 이후 영상 편집은 APK 기능을 변경하지 않는다.

## 251–260

- 소개·문제·해결·차별점·기술 구조·시연·UI·테스트 문서를 실제 확인 범위로 작성했다. 프로젝트 안의 공식 공모전 규정과 제출 양식은 발견하지 못했다.
- 최종 Debug APK의 데이터 유지 업데이트와 계측 29개, Python 13개, JVM 10개가 통과했다. v2 서명과 파일 크기·SHA-256을 기록했다.
- 대체 시험 알람을 앱 백그라운드에서 확인했다. am kill은 이 환경에서 프로세스를 제거하지 않아 별도로 검증된 앱 PID만 종료했다. PID 소멸 후 45.263초 지연으로 알람 수신과 프로세스 재생성을 확인했다.
- 실제 수신한 시험 알람을 끄고 검증 여행을 종료·보관했다. 수동 노을의 재시작 복원 후 자동 테마로 돌아왔다.
- 기존 여행 2건과 이전 검증 여행 1건의 전체 열 해시가 보존됐다. 이번 검증 여행 1건이 추가돼 총 네 건이다.
- 전체 패키지는 outputs/CHABAK_FINAL_SUBMISSION에 있으며 원본 네 편·편집본·캡처·문서·APK·산출물 목록을 포함한다.
