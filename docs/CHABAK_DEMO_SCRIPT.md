# CHABAK 공모전 시연 순서

## 시작 전

최신 Debug APK를 빌드하고 Pleos Connect API 34 AVD에서 설치·실행한다. 테스트 여행을 따로 생성하고 앱 데이터 초기화나 제거 없이 진행한다. 고캠핑 8085 서버의 실제 인증과 경기·숲 추천을 리허설에서 확인한다. 데이터 출처와 제한사항을 발표 슬라이드에도 구분한다.

| 순서 | 조작 | 확인할 내용 | 실패 시 |
| --- | --- | --- | --- |
| 1 | 홈에서 차박지 찾기 | 경기, 숲, 화장실 필수, 전기 필수 → 추천 보기 | 연결 실패 안내를 그대로 보여주고 공식 결과 시연을 중단 |
| 2 | 추천과 상세 비교 | 최대 5곳, 화장실·샤워실·개수대, 예약 링크, 출처 | 허용·충전·주차·취사는 확인 필요로 설명 |
| 3 | 장소 선택 → 준비물 | 날짜·인원·숙박을 조정하고 한 항목 체크 | 저장 오류가 있으면 다음 이동 단계로 넘어가지 않음 |
| 4 | 이동 정보 → 가는 길 | 차량이 허용하는 상태에서 목적지·거리·시간 확인 | SDK 연결 실패 또는 경로 검증 필요 상태를 설명 |
| 5 | 스마트 에너지 | SoC, 용량, 소비전력, 숙박 시간, 최소 잔량 | 시뮬레이션 사용 시 가상 값임을 화면에서 먼저 표시 |
| 6 | 차박 중 → 스마트 모닝 | 자연음 한 종류 재생·정지, 시험 알람·취소 | 정확한 권한이 없으면 대체 알람 지연을 안내 |
| 7 | 앱 종료·재실행 → 내 여행 | 같은 여행의 장소·날짜·체크 복원과 귀가 계획 | 여행 데이터 복원을 검증한 경우에만 시연 완료로 기록 |

발표에서는 공공데이터 게이트웨이, SQLite tripId 분리, SDK 조회와 추정값 구분을 설명한다. 실제 Gleo 음성은 시연에 넣지 않는다. ADB 결과는 해당 APK에서 별도로 성공한 경우에만 인텐트 검증으로 소개한다.
