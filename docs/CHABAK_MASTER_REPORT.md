# CHABAK 작업 기록

## STEP 066 변경 전 점검

- MainActivity의 Compose 라우터가 AppState와 SQLite TripStore를 연결한다. 여행별 장소·일정·준비물·이동·에너지 계획은 tripId로 저장하며 화면 탐색 스택과 일부 UI 상태는 메모리에서 관리한다.
- Gleo는 시작 및 기존 인스턴스 인텐트를 소비해 추천 결과 콜백을 반환한다. 자체 STT/TTS 코드는 제거됐다. 자연음 MediaPlayer와 스마트 모닝 수신기·포그라운드 서비스는 별도 실행 경로다.
- 고캠핑과 도로공사 Python 게이트웨이는 각각 8085와 8086을 사용한다. 추천은 실패 시 결과를 비운다. 탐색 화면의 내장 참고 목록에는 별도 실패 문구가 있다.
- NaviHelper는 좌표와 목적지 응답을 검증한다. 실제 방향별 도로 링크는 일반 안내 응답에서 연결되지 않는다. Vehicle SDK는 SoC와 용량을 읽으며 수동 시뮬레이션을 별도 표시한다.
- 준비물은 캠핑장·계절·인원·숙박을 반영한다. 날씨 관측은 방문일 조건이 맞을 때만 사용한다. 검증된 노지 장소는 0건이다.
- MainActivity에 화면·알람·오디오가 함께 있어 변경 시 회귀 범위가 넓다. 참조 캠핑장과 고캠핑 목록의 데이터 성격이 다르고, 검색과 추천에는 일부 공통 필터가 있다. 제거된 캐릭터의 이미지 리소스는 남아 있다. 이 점검 단계에서 기능과 리소스는 변경하지 않았다.
- 우선순위는 빌드·실행 복구, 실제 API와 화면 비교, 여행 A/B 검증, SDK 실행 검증, 문서화 순서다.

## 검증 범위와 시연 판정

- 공식 Pleos 피드는 접속했다. Pleos 에뮬레이터나 실제 차량에서 수신한 데이터는 없다. Python 테스트의 공식 API 응답은 모의 자료이며, Vehicle 시뮬레이션은 이번에 실행하지 않았다.
- 8085 응답은 테스트 서버 프로세스의 인증 상태와 일치하지 않았다. 분리 포트 무키 테스트를 통해 현 소스의 실패 처리만 확정했다. 고캠핑·도로공사 인증 설정과 Pleos 이미지 설치를 사용자 환경에서 확인해야 한다.
- 다음 우선순위는 Gradle 복구, Pleos AVD 연결, 공식 데이터와 여행 복원 검증, 차량 기능 실행, 도로공사·노지 데이터 검증이다. 세부 절차는 CHABAK_NEXT_STEPS.md에 있다.
- **판정 3 — 핵심 오류로 시연 불가.** 현재 환경에서 최신 APK를 생성하거나 Pleos 실행 대상으로 앱 흐름을 시연할 수 없다. 코드 직접 컴파일 및 백엔드 테스트 결과는 확인했다.
